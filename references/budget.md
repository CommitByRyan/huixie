# 徽写 · 上下文预算

## 问题

长篇写到中后期，单章上下文会自己长胖：本章要点只有几百字，历史设定却越堆越多。如果装配时不设上限，模型拿到的 90% 输入是「跟本章无关的历史」，注意力被稀释，token 成本线性上升，写到 200 章会直接撞上下文上限。

徽写的做法：**给上下文定硬预算，超了就按既定顺序降级，并记录降级档位。**

## 预算表

| 层 | 预算（字符） | 内容 |
|---|---|---|
| static | 4000 | 世界观（默认 5 段）/ 力量体系 / 禁词 / 姓名红线 / 角色卡（默认 6 张） |
| arc | 1200 | 本卷主线 / 本季主线 / 季末钩子 |
| window | 3500 | 近 3 章摘要（各 150 字）/ 上一章末尾 900 字 / 本章要点 |
| state | 2500 | 主角面板 / 物品栏（前 10）/ 活跃 NPC（默认 5）/ 相关伏笔（默认 12 条，单条 48 字） |
| beats | 800 | 本章节拍表 |
| **合计** | **12000** | 硬上限，超过即降级 |

## 降级阶梯

只在总量超出 12000 时才逐级施加，每次只降一档，降完重新计算：

| 档 | 动作 |
|---|---|
| T1 | 伏笔 12 → 8 |
| T2 | NPC 5 → 3 |
| T3 | 世界观 5 → 4 段 |
| T4 | 近章摘要 3 → 2 条 |
| T5 | 伏笔 8 → 5 |
| T6 | 世界观 4 → 3 段 |
| T7 | 角色卡 6 → 3 张，伏笔描述 48 → 32 字 |

阶梯用尽仍超预算时，各层再按自身预算硬裁（在句读处截断，不截半句），并在报告里标 `over_cap: true`——这时应该考虑拆章，而不是继续加预算。

**降级不是静默丢弃**：每一档都写进 `assemble --json` 的报告，作者能看到「这一章我砍了什么」。

## 相关度而不是时间顺序

伏笔不是按「先埋先显示」取，而是按相关度打分（见 `state-model.md`）。一条第 1 章埋、第 21 章该兑的线，会比第 160 章刚埋但没到期的那条优先进入上下文。

## 为什么这能省 80% 以上

用一本 160 章规模的连载档案做只读基准（数据已脱敏：只保留结构与量级，装配下一章，不改动原作）：

| 项 | 全量注入（旧做法） | 徽写装配 |
|---|---|---|
| 总字符 | **87,590** | **4,133** |
| 压缩比 | — | **4.7%** |
| 降幅 | — | **95.3%** |
| 降级档位 | — | T0（未触发降级） |
| 伏笔条数 | 400+ 条全量 | 12 条（按相关度） |

分层实测：静态 1,675 / 卷季 0（该章已超出原卷区间）/ 滑窗 1,308 / 状态 925 / 节拍 225。

关键在于三件事，而不是简单截断：

1. **已兑现的伏笔不注入**——全量账里约四成已收线，直接排除。
2. **未到期且不相关的伏笔只留名字级摘要**——单条描述从 181 字压到 48 字。
3. **全量账不删**——留在 `state.json` 供 `status` 与终检查询，只是不进每章的上下文。

一句话：上下文是**投影**，不是**账本**。把账本塞进上下文，是长篇后期注意力涣散和成本失控的共同来源。

## 调参

预算写在 `scripts/budget.py` 顶部的 `SECTION_BUDGET` 与 `CAP`。不同平台、不同模型窗口可以各自调整，但**建议保持总上限不超过 12000 字符**（约 7.5k tokens），给正文输出留出足够空间。
